# Driver Flow Update: Arrived at Drop Location → Verify OTP → Collect Payment

## Summary
Updated the driver app flow to include a dedicated "Arrived at Drop Location" step with 6-digit OTP verification before proceeding to payment collection.

## Changes Made

### 1. Updated Active Ride Screen (`apps/driver/app/ride/[id].tsx`)

**Button Flow Changes:**
- **When status = `in_progress`**: Button now shows "Arrived at Drop Location" (previously "Complete & Collect Payment")
- Clicking the button navigates to `/ride/verify-drop-otp` instead of `/ride/collect-payment`

**Status Badge Updates:**
- `in_progress` status now shows "🚚 On the way to drop-off" (previously "🚚 Trip in progress")

**Pickup OTP Hint:**
- Updated text to clarify "Ask customer for 4-digit OTP to start trip"

### 2. Created New Verify Drop OTP Screen (`apps/driver/app/ride/verify-drop-otp.tsx`)

**Purpose:** Dedicated screen for verifying 6-digit delivery OTP

**Features:**
- 6-digit OTP input fields (vs 4-digit for pickup)
- Clean UI matching the pickup OTP verification screen
- Validates OTP against `booking.delivery_otp`
- On successful verification:
  - Sets `delivery_confirmed_at` timestamp
  - Navigates to `/ride/collect-payment` screen
- Shows receiver information
- Includes helpful instructions and error messages

**Flow:**
```
Verify Drop OTP → [Success] → Collect Payment Screen
```

### 3. Updated Collect Payment Screen (`apps/driver/app/ride/collect-payment.tsx`)

**OTP Verification Logic:**
- Skips OTP verification if `delivery_confirmed_at` is already set (from verify-drop-otp screen)
- Shows green "Delivery Verified ✓" badge when OTP is confirmed
- Only shows OTP input if somehow not verified yet (fallback)

**UI Updates:**
- When delivery is confirmed: Shows success state with checkmark icon
- Text: "OTP successfully verified"

## Complete Driver Flow Now

```
1. Accept Ride
   ↓
2. Navigate to Pickup → "Arrived at Pickup" button
   ↓
3. Driver Arrived Status → "Verify OTP & Start" button  
   ↓
4. Pickup OTP Screen (4-digit) → Verify & Start Trip
   ↓
5. Trip In Progress → Navigate to Drop-off → "Arrived at Drop Location" button [NEW STEP]
   ↓
6. Delivery OTP Screen (6-digit) [NEW SCREEN] → Verify & Complete Delivery
   ↓
7. Collect Payment Screen → Confirm Payment & Complete Trip
   ↓
8. Trip Complete
```

## Key Differences Between Pickup and Delivery OTP

| Aspect | Pickup OTP | Delivery OTP |
|--------|-----------|--------------|
| Digits | 4-digit | 6-digit |
| Purpose | Verify pickup and start trip | Verify delivery and proceed to payment |
| Screen | `/ride/verify-otp` | `/ride/verify-drop-otp` |
| Next Screen | Active ride (trip in progress) | Collect payment |
| DB Field | `pickup_otp` | `delivery_otp` |
| Confirms | `started_at` | `delivery_confirmed_at` |

## Database Schema

The flow uses these existing booking fields:
- `delivery_otp` (VARCHAR) - 6-digit OTP generated when trip starts
- `delivery_confirmed_at` (TIMESTAMPTZ) - Set when OTP is verified

## Notes

- The delivery OTP is automatically generated by the `initiate_delivery_otp()` RPC function
- SMS notification is automatically queued and sent via the `send-sms` edge function
- The verify-drop-otp screen ensures delivery confirmation before payment collection
- This separation improves UX by breaking the flow into logical steps
