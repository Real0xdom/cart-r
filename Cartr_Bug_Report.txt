BUG-006 — [CRITICAL]
All Documents Must Fully Upload to Supabase Before Redirecting to Verification Screen
────────────────────────────────────────────────────────────
Module:   Driver App → Document Upload → Verification Pending | Admin → Driver Approval Page
Priority: CRITICAL

Summary:
Drivers are redirected to the Under Review screen before documents have finished uploading. Admin sees No File for vehicle photo in the approval panel.

Problem Statement:
  • App navigates to verification screen regardless of whether file uploads completed
  • Race condition: DB record is written before storage upload resolves
  • Admin sees No File for vehicle photo because upload had not resolved when record was saved
  • No retry or error handling if a single document upload fails

Developer Tasks:
  1. Refactor submission flow: upload ALL documents to Supabase storage using Promise.all() — wait for ALL promises to resolve
  2. Only after ALL storage uploads succeed, write the driver record to DB with resolved public URLs
  3. If any upload fails, show an error toast with the specific document name and a retry button — DO NOT submit
  4. Show loading state during upload+submit: Uploading documents... X of Y
  5. After all uploads and DB write succeed, THEN navigate to Verification Pending screen
  6. In admin panel: add null check for document URLs — show Not Uploaded with a red badge instead of blank

Notes:
  Use Promise.all([uploadDoc1, uploadDoc2, uploadDoc3]) then save record. Do NOT use Promise.allSettled — any failure should block submission.

BUG-020 — [CRITICAL]
Payment Completion Flow Needs Multi-Step Confirmation — Single Tap Is a Major Risk
────────────────────────────────────────────────────────────
Module:   Driver App → Drop Location → Payment Collection → Trip Completion
Priority: CRITICAL

Summary:
Tapping Complete and Collect Payment immediately marks trip as done and assumes payment was received. This is a critical business logic flaw.

Problem Statement:
  • Single tap completes trip AND marks payment received — no confirmation step
  • If driver taps button accidentally, trip is completed and customer charged with no recourse
  • No verification that payment was actually received before trip is marked complete
  • This flow differs from industry standard — Porter, Swiggy Genie, Dunzo all use multi-step confirmation

Developer Tasks:
  1. Redesign drop-location flow as multi-step: Step 1 — Driver arrives: show I Have Arrived button. Step 2 — Delivery confirmation: customer OTP or customer confirms receipt. Step 3 — Payment collection: show amount + options (Cashfree in-app or Cash). Step 4 — Payment confirmed: only after success callback or explicit Cash Collected confirmation with double-confirm dialog → mark trip complete. Step 5 — Trip Complete summary screen.
  2. Add confirmation dialog before any irreversible action: Are you sure you want to mark this trip as complete? This cannot be undone.
  3. For cash: show Confirm Cash Received → secondary: You are confirming receipt of Rs.[amount] in cash. Confirm?
  4. Log all payment events with timestamp, method, and driver confirmation in Supabase
  5. Study Porter and Dunzo flows — both require explicit payment confirmation before trip close
  6. Add a Raise Issue option for cases where payment was not received despite trip being marked complete

Notes:
  Revenue-critical bug. Reference: Porter cash confirmation modal, Dunzo OTP + payment before completion.
